# Decisions (append-only)

Format: `YYYY-MM-DD — decision — why`

- 2026-10-03 — pnpm + Turborepo monorepo: `apps/mcp`, `apps/web`, `packages/core` — one repo for the team, shared types.
- 2026-10-03 — MCP hosted as a Next.js route with `mcp-handler` v2 (Streamable HTTP, stateless) — deploys to Vercel as-is, no Redis.
- 2026-10-03 — MCP and web are separate Vercel projects — MCP is the product; web is a viewer.
- 2026-10-03 — In-memory seeded store behind a `Store` interface for the first build — speed. **Consequence:** data resets on cold start and is not shared between web and mcp deployments. Next step is a real DB.
- 2026-10-03 — Keyword matching (`packages/core/src/match.ts`) — good enough for demo; upgrade to embeddings via AI Gateway later.
- 2026-10-03 — No auth yet — public directory; add before letting anyone write in prod.
- 2026-10-03 — Hosted agents = skills, not runtimes: instructions + context notes + scoped connector actions, served over MCP. The *caller's* LLM reasons; we never run an agent loop, cron or schedule — matches "humans out of the loop via natural language" with zero infra.
- 2026-10-03 — Visvine is infrastructure only (`POST https://visvine.com/api/actions/<name>`, bearer): `edit_context`/`read_context` for notes, connector notes (`connectors/<handle>-<name>.md`) + `run_connector` for external calls, `set_connector_secret` for keys. Visvine's agent system is NOT used.
- 2026-10-03 — One platform Visvine space/token holds every agent's notes and connectors; Agents Space enforces ownership and scope. Connector names are namespaced by owner handle. Callers can only run *declared* actions an owner attached — never raw code, never secrets.
- 2026-10-03 — API keys (`as_...`, sha256-hashed) instead of OAuth — fastest path; `?key=` accepted for clients that can't set headers (leaks into logs; replace with OAuth later).
- 2026-10-03 — Registry persisted as one private JSON note (`agentspace/registry.md`) in Visvine, reloaded when >5s stale — persistence + web/mcp sharing without adding a DB. Last write wins; swap for Postgres when it matters.
- 2026-10-03 — Private agents are listed in search (marked "request access") but instructions/actions are hidden until the owner approves.
- 2026-10-03 — Secrets: we forward to Visvine write-only and never store/echo them. Connector notes hold `{{secret:NAME}}` references only.
- 2026-10-03 — Web UI is light only with a blue accent (#2563eb). Layout is a left sidebar (logo, search, people) with the agent card grid on the right. Hero, section labels and the bottlenecks list are gone. Why: user asked for a directory look, not a landing page.
- 2026-10-03 — **Supersedes the Visvine entries above.** Connectors, context notes, secrets and the registry now live in Agents Space itself; no external runtime. — The MCP is our product; it shouldn't depend on another platform's servers.
- 2026-10-03 — Database: Supabase Postgres via Prisma 7 (`prisma-client` generator, `@prisma/adapter-pg`). `DATABASE_URL` = pooled (6543) for the apps, `DIRECT_URL` = direct for the CLI. In-memory `Store` remains as the no-DB fallback. — Team choice; adapter-pg works with Supabase's transaction pooler.
- 2026-10-03 — Connector actions are declarative (HTTP request templates with `{{args.x}}` / `{{secret.X}}`, or remote-MCP `list_tools` / `call_tool`), not builder JS. — Running untrusted code needs a sandbox (cost, latency); templates cover most REST APIs and are safe to run in our functions.
- 2026-10-03 — Outbound safety: host must be fixed in the template and in the connector's allowlist; private/loopback hosts rejected; path/query args URL-encoded; redirects not followed; 30s timeout; 50KB response cap; secret values redacted from results.
- 2026-10-03 — Secrets encrypted with AES-256-GCM (`CONNECTOR_SECRETS_KEY`), stored in `ConnectorSecret`, decrypted only per request. — Owners need write-only secrets; key rotation = owners re-set secrets.
- 2026-10-03 — Monorepo uses one root `.env.local`; Next configs load it via `process.loadEnvFile`, Prisma config via dotenv.
- 2026-10-03 — Landing page at `/` coded from the "Agent Space — Landing" frame in the Pencil file `~/Pens/AgentSpace.pen` (components in `apps/web/components/landing/`); the agent directory (Agent Book UI) moved to `/directory` — the design is the public face; the directory stays reachable from nav/footer.
- 2026-10-03 — Landing is light-only (pins `bg-white text-ink` on its root) and its tokens (`ink`, `muted`, `edge`, `panel`, `wait`, `dark-*`; `edge`/`panel` named to avoid clashing with the directory's `line`/`surface`) mirror the .pen variables in `globals.css` `@theme` — keeps code in sync with the design file.
- 2026-10-03 — Landing motion is CSS-only plus one tiny client observer (`components/landing/motion.tsx`): blocks marked `data-animate` get `data-in` when scrolled into view; children use reveal classes (`.r`, `.r-pop`, `.r-mask`, `.r-type`, `.r-draw`…) staggered by `--d` (helper `d(ms)` in `primitives.tsx`). No animation library. Keyframes use `animation-fill-mode: backwards` so hover transforms still work after reveal. `prefers-reduced-motion` shows everything statically. — Zero deps, server components stay server components.
- 2026-10-03 — Network diagram packets ride CSS motion paths (`offset-path: path(...)`) on the same `d` strings as the SVG lines; lines draw with dasharray = explicit `--len` per path (not `pathLength`, which Chrome mis-scales on curves).

## 2026-10-03 — Supabase Auth with Google for sign-in
- Humans sign in on the web with Google via Supabase Auth (`@supabase/ssr`, server-side PKCE flow, `proxy.ts` refreshes the session). Our `User` row is linked by `authId` (auth.users.id) and created on first sign-in, handle derived from name/email.
- The MCP keeps API keys (most MCP clients can't run a browser OAuth flow yet); signed-in users generate/rotate one at `/account`. The MCP also accepts a Supabase access token as Bearer (verified with `getClaims`), so a client that has one needs no key.
- `keyHash` is now nullable: web accounts have no key until they generate one. `create_account` over MCP still works.
- 2026-10-03 — MCP OAuth = Supabase Auth's OAuth 2.1 server (not our own AS). MCP serves only resource-server pieces: protected-resource metadata + token verification (`getClaims`). Google is configured as a Supabase provider, so the Google client id/secret live in Supabase, not app env. — Least code, one identity system shared with web sign-in; Supabase handles DCR, PKCE, refresh tokens.
- 2026-10-03 — When Supabase is configured, `/mcp` requires sign-in (401 + WWW-Authenticate) — MCP clients only start OAuth on a 401, so optional auth would never prompt. Anonymous discovery moves to the website; public per-agent endpoints stay anonymous. An invalid/expired token is always a 401 so clients refresh.
- 2026-10-03 — Schema ownership moves from Prisma to Supabase declarative schemas (`supabase/schemas/` → generated `supabase/migrations/`). The baseline was exported from the Prisma model and verified identical to the live database. Change tables in `supabase/schemas/`, never with `pnpm db:push` / `db:migrate`. — One owner for the database; RLS, grants and policies can only be expressed on the Supabase side. **Consequence:** while the app still queries through the Prisma client, `prisma/schema.prisma` is a mirror: refresh it with `prisma db pull` after each schema change.
- 2026-10-03 — CLI device login (`agents-space login` → code → approve at web `/device` → CLI polls and gets an API key, then runs `claude mcp add --header`). — Claude Code's built-in MCP OAuth always redirects to `http://localhost:<port>/callback`; a device flow keeps the whole sign-in on our domain. Approving rotates the user's single API key (multiple keys per user would need an `ApiKey` table). Device codes are stored hashed, expire in 10 minutes and are single-use. Known gaps: `/api/device/start` is unauthenticated and not rate-limited; the client name shown on `/device` is supplied by the caller.
- 2026-10-03 — `AGENTS.md` is the canonical agent guide (read by Codex, Cursor, Claude…); `CLAUDE.md` is just `@AGENTS.md`. Tool-managed blocks (turbo, next) stay at the end of the AGENTS.md files. — One source, no drift between tools.
- 2026-10-03 — Web deploys from the repo root with the Vercel CLI to project `agents-space` (SUPAYAPPERS, root dir `apps/web`); `.vercelignore` excludes all `.env*` so local tokens/DB creds never upload (next.config would otherwise load them). — Monorepo needs the root uploaded for workspace deps.
- 2026-10-03 — Landing hero shows real personal agents (Muse/Meta, Instinct/Spear Street, Grok Bot/xAI, Claude/Anthropic, ChatGPT/OpenAI) calling spaces (Emma, Tony’s Pizza SF, David, Marco’s) in a rotating, illustrative feed (`components/landing/agent-calls.tsx`), plus a logo marquee. Logos are the products’ own marks in `apps/web/public/agents/`, shown with a non-affiliation disclaimer. Dot (New Computer) was left out — it shut down Oct 2025. — Makes "let your agent talk to mine" concrete with agents people already use.
- 2026-10-03 — Supersedes the `agents-space` deploy entry: the web lives on Vercel project `agents-space-web` (with prod env: DB, Supabase, MCP URLs) and the MCP on `agents-space-mcp`. The duplicate `agents-space` project (agents-space-liard.vercel.app, no env) was deleted. — One host per app.
- 2026-10-03 — Agent pages show the skill (instructions, notes, scoped actions) only to callers with access (`store.hasAccess`), matching `use_agent`; others see the public listing. Secrets are settable from the web but never displayed.
- 2026-10-03 — OAuth `redirectTo` carries no query string (`next` goes in a cookie): Supabase falls back to the Site URL (production) when redirectTo doesn't match the allowlist exactly.
- 2026-10-03 — Callers with access see a connector only as title, description and action names/descriptions. Hosts, URLs, headers, secret names and secret status are owner-only (ConnectorCard `owner`).
- 2026-10-03 — Positioning follows the landing page: Agent Space gives a person or business its own "space" (an MCP) that other people's agents can reach, so the owner stops being the bottleneck. The directory is the opt-in discovery layer, not the core product. `context.md` was rewritten to match. — Decided by the founder; the landing page explains the idea best.
- 2026-10-03 — Claim your space is MCP-first: the landing checks the handle, then hands out the MCP URL with `?claim=<handle>`. The claim happens only after Google sign-in (users with `authId`; API-key-only accounts can't claim), on the first signed-in request, so handles go to real accounts. The landing check reserves nothing. For Claude Code the landing hands out `npx agents-space@latest login --claim <handle>` (device login, then the CLI adds the MCP URL with `?claim=`); the device-login key belongs to a Google-signed-in user, so the rule holds. — Claiming also installs the product; verified accounts stop squatting.
- 2026-10-03 — A space = hosted agent with `id = handle`, category `Space`, private and published by default, served at `/<handle>/mcp` (and `/a/<handle>/mcp`). No schema change. Handles lock once a space exists. Generated agent ids skip existing handles and the reserved list (`RESERVED_HANDLES`) so an agent can't take someone's address. Private spaces are left out of the directory. — Avoids a migration; one handle = one stable address.
- 2026-10-03 — Local `DATABASE_URL` / `DIRECT_URL` use the Supavisor pooler host (`aws-0-us-west-2.pooler.supabase.com`, user `postgres.<ref>`), not `db.<ref>.supabase.co`. — The direct host is IPv6-only and unreachable from IPv4-only networks (EHOSTUNREACH); the pooler works on IPv4.
- 2026-10-03 — All public tables are RLS-enabled with no policies and no anon/authenticated grants; default table privileges for anon/authenticated were removed for tables created by `postgres` (the `supabase_admin` defaults are untouched). Access is only via Prisma as `postgres` (bypasses RLS); any future Data API use needs explicit policies + grants. Sequence and function default privileges for anon/authenticated are still open, so any future `SECURITY DEFINER` function in `public` must revoke EXECUTE explicitly. — The publishable key is public, so open grants exposed every table over PostgREST.
- 2026-10-03 — People reach each other through the one `agents-space` MCP, not by installing each other's spaces: `ask_space(handle)` runs as the signed-in caller and checks the owner's whitelist. `/<handle>/mcp` stays as a direct link for agents outside Agents Space. Whitelisting reuses `AccessRequest` (owner-created, approved). — Install once, call anyone by handle; no migration.
- 2026-10-03 — Agent visibility has four modes: `public` (listed, anyone uses), `listed` (listed, info open, use needs approval), `restricted` (listed and readable only for approved users; others with the link see the name and can request access), `private` (owner only, indistinguishable from a missing agent). Old `private` maps to `listed`, except spaces (category `Space`) which map to `restricted` (migration `visibility_backfill`); new spaces default to `restricted`. Revocation reuses `AccessRequest` status `denied` (no enum change). With OAuth on, every non-public per-agent id (unknown, draft, private, listed, restricted) gets the same sign-in challenge; without OAuth unreachable ids 404. — A secret agent must not be discoverable by probing ids; modes are an enum extension, so no table change.
- 2026-10-03 — Ids and handles are a public namespace: id collisions (`register_agent`/`create_agent` suffixing, `/api/handles/<h>`, `claim_space`) reveal that an id is taken, including by a private or draft agent, but nothing about it. Accepted limitation. — Always-suffixed ids would make every agent URL ugly.
